# Правила составления вопросов для ГОСТ-бота

Бот учит конструкторов (пресс-формы для резиновых изделий) требованиям ЕСКД. Каждый вопрос — один факт из стандарта, проверяемый по пункту.

## Формат (YAML, список)
```yaml
- id: "305-101"                     # уникальный; диапазон номеров выдан в задании
  gost: "2.305"                     # код из data/gosts.yaml
  ref: "ГОСТ 2.305-2008, п. 6.13"   # стандарт + пункт/таблица/рисунок — точно
  image: "305_half.png"             # необязательно; только из docs/images.md
  q: "Текст вопроса?"               # до ~180 символов
  options: ["Верный", "Неверный", "Неверный", "Неверный"]   # 2–5 вариантов, до ~90 символов каждый
  answer: 0                         # индекс верного (с 0); варианты при показе перемешиваются
  explain: "Пояснение 1–2 предложения: почему так, с цифрами."   # до ~280 символов
  level: 1                          # 1 базовый, 2 средний, 3 тонкости
  fixed: true                       # ТОЛЬКО если варианты — буквы/цифры меток на картинке (не перемешивать)
```
Строки со спецсимволами (двоеточие, кавычки, #) берите в двойные кавычки. Внутри используйте «ёлочки».

## Точность — главное
1. Источник истины — файлы `research/part1_*.md`, `part2_*.md`, `part3_*.md`. Нормы с пометками [НЕ ПОДТВЕРЖДЕНО], [РИС.] или «источники расходятся» не делайте правильным ответом. Исключение — когда пометка снята в самом файле (например «безопасный ответ — …»).
2. Если нужного факта в research нет, можно взять из текста стандарта через WebFetch (meganorm.ru, docs.cntd.ru; не более 8 загрузок на всю работу). Без подтверждения факт не берите — лучше спросите о другом.
3. Ровно один верный вариант. Неверные — правдоподобные (соседние числа, соседние типы линий, нормы из соседнего пункта), но однозначно неверные. Не используйте «все перечисленное» и «ни одно из».
4. ref — пункт, где норма есть на самом деле.
5. Пояснение не противоречит ответу и не добавляет непроверенных фактов.

## Разнообразие
- Не повторяйте существующие вопросы из `data/questions/*.yaml` (прочитайте их). Можно спросить тот же факт с другой стороны («какой минимум?» → «какое значение нарушает норму?»), но не перефразировать.
- Типы вопросов: значение/число; «для чего применяют»; «что обозначает»; «какая запись верна»; ситуационные («конструктор сделал X — верно ли?»); «верно ли утверждение» (Да/Нет с уточнением — в меру, не более 15 % файла).
- Привязка к отрасли (пыльники, манжеты, втулки, пресс-формы, резина) приветствуется, если от неё не меняется суть нормы.
- Картинки: используйте подходящие из `docs/images.md` (можно повторно, с новым вопросом о другой метке/аспекте). Вопрос обязан точно соответствовать тому, что нарисовано. Не ссылайтесь на картинки, которых нет. Если картинки нет — не указывайте image.
- Сложность: примерно 45 % level 1, 40 % level 2, 15 % level 3.
